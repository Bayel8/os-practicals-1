# Практическая работа № 6. Синхронизация

## 1. Цель работы

Изучить механизмы синхронизации потоков, устранить ошибки взаимодействия потоков и реализовать задачу «производитель–потребитель» с кольцевым буфером.

## 2. Окружение

- ОС: Ubuntu через WSL2.
- Язык программирования: Python 3.
- Модуль threading: потоки, мьютексы, семафоры, условные переменные и барьеры.
- Модуль collections.Counter: подсчёт количества обработок каждого элемента.

Дополнительные библиотеки не требуются.

## 3. Структура проекта

- producer_consumer_semaphore.py — кольцевой буфер с семафорами и мьютексом.
- producer_consumer_condition.py — кольцевой буфер с мьютексом и условной переменной.
- barrier_demo.py — синхронизация четырёх потоков на трёх фазах.
- lost_wakeup_demo.py — демонстрация пробуждения без выполнения ожидаемого условия.

## 4. Задача «производитель–потребитель»

В обеих реализациях используются:
- 3 производителя;
- 2 потребителя;
- кольцевой буфер на 5 элементов;
- 1000 элементов от каждого производителя;
- 3000 элементов всего.

### 4.1. Реализация с семафорами

Используются два семафора:

- empty — количество свободных ячеек буфера;
- full — количество занятых ячеек.

Мьютекс mutex защищает общие данные: позиции чтения и записи, содержимое буфера и количество элементов.

Производитель ожидает свободную ячейку, записывает элемент и увеличивает число занятых ячеек. Потребитель ожидает готовый элемент, извлекает его и освобождает ячейку.

### 4.2. Реализация с условной переменной

Используется threading.Condition, которая объединяет мьютекс и механизм ожидания уведомлений.

Производитель ожидает, пока буфер не станет свободным. Потребитель ожидает, пока буфер не станет непустым.

Условия проверяются через while, потому что после пробуждения поток должен повторно проверить состояние буфера. notify_all() уведомляет ожидающие потоки об изменении состояния.

## 5. Проверка корректности

В программах проверяются следующие инварианты:

1. Число элементов в буфере всегда находится в диапазоне от 0 до 5.
2. Обработано ровно 3000 элементов.
3. Каждый элемент обработан ровно один раз.
4. Потерянных или лишних элементов нет.
5. После завершения буфер пуст.
6. Ошибки инвариантов отсутствуют.
