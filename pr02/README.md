# Практическая работа №2. Системные вызовы Linux

## 1. Цель работы

Изучить обработку лог-файлов с помощью Bash, чтение файлов в Python и наблюдение за системными вызовами Linux с помощью strace.

## 2. Структура проекта

- `report.sh` — анализ лог-файлов и подсчёт записей.
- `hello.py` — чтение файла и вывод его размера в байтах.
- `data/` — тестовые лог-файлы.
- `trace.txt` — трассировка запуска Python.
- `trace_cat.txt` — трассировка команды cat.

## 3. Анализ лог-файлов

Скрипт `report.sh` принимает путь к каталогу и уровень записей `ERROR` или `WARN`. Дополнительно поддерживается параметр `--top N`, ограничивающий количество результатов.

Примеры запуска:

    ./report.sh data ERROR
    ./report.sh data WARN
    ./report.sh data WARN --top 2

Скрипт проверяет аргументы и существование каталога, подсчитывает записи по модулям и сортирует результат по убыванию количества.

Для тестирования использованы синтетические лог-файлы.

Ожидаемые результаты для тестовых данных:

- ERROR: модуль net — 100 записей, api — 50 записей.
- WARN: модуль api — 50 записей, database — 50 записей.

## 4. Чтение файла в Python

Программа `hello.py` открывает файл в бинарном режиме, читает его содержимое и выводит размер в байтах.

Запуск:

    python3 hello.py data/01.log

Для записи системных вызовов используется команда:

    strace -f -o trace.txt python3 hello.py data/01.log

Параметр `-f` позволяет отслеживать дочерние процессы, а `-o trace.txt` сохраняет трассировку в файл.

## 5. Сравнение системных вызовов

Для сравнения использованы команды:

    strace -f -o trace.txt python3 hello.py data/01.log
    strace -f -o trace_cat.txt cat data/01.log > /dev/null

Python обычно выполняет больше системных вызовов, поскольку при запуске интерпретатора загружаются библиотеки и инициализируется среда выполнения. Команда cat предназначена для вывода содержимого файла и обычно требует меньше подготовительных операций.

Точное количество системных вызовов определяется по сохранённым трассировкам.

## 6. Ответы на вопросы

### Почему пользовательская программа не может напрямую обращаться к диску?

Пользовательская программа работает в ограниченном режиме доступа. Для операций с файлами и устройствами она обращается к ядру операционной системы через системные вызовы. Ядро проверяет права доступа и выполняет необходимые операции.

### Что дороже: вызов функции или системный вызов? Почему?

Обычно системный вызов дороже обычного вызова функции. Он требует перехода из пользовательского режима в режим ядра и обратно, а также дополнительных проверок и обработки операционной системой.

## 7. Вывод

В ходе работы создан Bash-скрипт для анализа лог-файлов и Python-программа для чтения файлов. С помощью strace получены трассировки системных вызовов Python и cat. Сравнение позволяет изучить накладные расходы при запуске интерпретатора и взаимодействии программы с операционной системой.
